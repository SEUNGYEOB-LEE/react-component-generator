# Commit

## 목적

작업 디렉토리의 변경사항을 분석하여, 프로젝트 컨벤션에 맞는 한국어 커밋 메시지로 커밋한다.

## 트리거

- "커밋해줘"
- "커밋"
- "변경사항 저장해줘"

## 절차

1. `git status`와 `git diff` (staged/unstaged 모두)로 변경사항을 분석한다.
2. 변경사항을 논리적 단위로 분류한다. 서로 관련 없는 변경은 별도 커밋으로 나눈다.
3. 각 단위에 대해 한국어 커밋 메시지를 작성한다. 형식: `feat/fix/refactor/chore: 요약`
   - `feat`: 새로운 기능 추가
   - `fix`: 버그 수정
   - `refactor`: 동작 변경 없는 코드 개선
   - `chore`: 빌드/설정/문서 등 그 외 변경
4. 커밋 전 사용자에게 어떤 파일을 어떤 메시지로 커밋할지 보여주고 승인을 받는다. 승인 없이 임의로 커밋하지 않는다.
5. 승인 후 해당 단위만 `git add`하고 커밋한다.

## 주의사항

- `.env`, credentials 등 비밀 정보가 포함된 파일은 커밋하지 말고 사용자에게 알린다.
- `git commit --no-verify`, `--amend` 등은 사용자가 명시적으로 요청하지 않는 한 사용하지 않는다.
