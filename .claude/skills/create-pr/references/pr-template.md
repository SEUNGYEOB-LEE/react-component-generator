# PR 본문 템플릿

아래 섹션을 실제 변경사항에 맞게 채운다. 해당 내용이 없는 섹션은 통째로 생략한다.

```markdown
## 요약

- 무엇을, 왜 변경했는지 1~3줄로 설명한다. "어떻게"보다 "왜"에 집중한다.

## 변경사항

- 논리적 단위로 묶어 bullet로 나열한다.
- 커밋 메시지를 그대로 나열하지 말고, 리뷰어가 읽기 쉽게 요약한다.

## 테스트 방법

- [ ] 리뷰어가 직접 확인할 수 있는 체크리스트 형태로 작성한다.
- [ ] 예: `bun run test` 통과 확인
- [ ] 예: 브라우저에서 OO 기능이 정상 동작하는지 확인

## 참고사항 (선택)

- 브레이킹 체인지, 후속 작업, 알려진 제약사항 등이 있으면 여기에 적는다.
```

## 작성 규칙

- 제목은 커밋 컨벤션과 동일한 형식을 따른다: `feat/fix/refactor/chore: 요약`.
- 본문은 한국어로 작성한다.
- diff에 없는 내용을 지어내지 않는다 — 실제 변경된 파일과 커밋 로그에서 확인한 사실만 적는다.
